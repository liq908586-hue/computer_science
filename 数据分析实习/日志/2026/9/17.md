三、分阶段计划

阶段一：Titanic（预计 3-5 天）

目标：跑通“数据加载 → 清洗 → 建模 → 提交”全流程，建立对数据分析代码结构的感知。

具体任务：

□ 在 Kaggle 创建 Notebook，加载 train.csv 和 test.csv
□ 用 Pandas 完成 EDA：查看缺失值、分布、生存率与性别/舱位的关系
□ 处理缺失值：Age 中位数填充、Embarked 众数填充、Cabin 转二值特征
□ 构造至少 2 个衍生特征（如称呼、家庭规模）
□ 用逻辑回归或随机森林建立基线，划分验证集评估
□ 生成 submission.csv 并提交，记录得分
□ 整理代码到 GitHub，写好 README

产出：GitHub 仓库 Titanic-ML，含 notebook + README + submission

阶段二：SQL + Excel 补齐（预计 1 周）

目标：掌握 SQL 查询和 Excel 透视表/可视化，能独立完成从数据库取数到报表输出的流程。

具体任务：

□ 学习 SQL 基础：SELECT、WHERE、GROUP BY、JOIN、聚合函数
□ 在 Kaggle 或本地用 SQLite 加载一个电商数据集，练习多表关联查询
□ 用 SQL 计算：复购率、各品类销售额、月度趋势
□ 将查询结果导出到 Excel，做透视表和图表
□ 产出一份简单的分析报告（含 3-5 张图表 + 结论）

产出：一份 Excel/SQL 分析报告，GitHub 仓库 Ecommerce-SQL-Analysis

阶段三：Olist 配送延迟分析（预计 2 周）

目标：做一个能体现“发现问题 → 量化归因 → 提出建议”完整链路的项目，作为简历核心项目。

具体任务：

□ 下载 Olist 数据集，理解 9 张表的关系
□ 用 SQL 关联订单表、评价表、客户表
□ 计算实际配送时间与预计时间的差值
□ 分析延迟天数与差评率的相关性（如延迟 3 天以上差评率是正常的几倍）
□ 按地区/品类拆解，找出延迟最严重的细分
□ 用 Python 或 Excel 做可视化
□ 写出完整分析报告：背景 → 方法 → 发现 → 建议 → 局限

产出：GitHub 仓库 Olist-Delivery-Analysis，含 SQL 脚本 + 分析报告 + 图表

阶段四：整理与投递

具体任务：

□ 确保 3 个仓库的 README 都包含：目标、数据、方法、结论、如何运行
□ 简历中每个项目用“业务背景 + 分析过程 + 量化结论”格式描述
□ 附上 GitHub 链接
□ 开始投递数据分析实习岗位
